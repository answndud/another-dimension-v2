# ADR 0002: Nostr relay 위의 Noise XX와 Ed25519 신원 증명

- 상태: 채택
- 관련: [architecture.md](../architecture.md) 3절

## 맥락

운영자가 필요한 서버 없이 두 사용자가 서로를 찾아 연결해야 합니다. 사용자끼리 IP를 직접 노출하지 않아야 하고, 중계자는 신뢰할 수 없습니다.

## 결정

- 전송은 공개 Nostr relay의 휘발성 이벤트(kind 20000)를 사용합니다. 사용자가 relay 목록을 설정합니다.
- 암호화는 `snow` 크레이트의 `Noise_XX_25519_ChaChaPoly_BLAKE2s`를 사용하고 알고리즘을 직접 구현하지 않습니다.
- Noise의 static 키는 연결마다 새로 만듭니다. 장기 신원은 별도의 Ed25519 키이며, 핸드셰이크 해시·역할·신원 키·세션 relay 키에 대한 서명을 암호화된 전송 안에서 교환해 결속합니다.
- 양쪽이 같은 확인 코드를 별도 경로로 비교하고 각자 확인해야 채팅 프레임을 주고받습니다. 코드는 핸드셰이크 해시와 두 신원 키, 그리고 양쪽이 무작위로 만든 값에서 나옵니다. 각 쪽은 자신의 값의 해시(커밋)를 서명한 증명에 담아 먼저 보내고 상대의 커밋을 받은 뒤에야 값을 공개하므로, 중간자가 두 연결의 코드를 맞추도록 값을 조정할 수 없습니다. 코드는 12자리 숫자(약 40비트)입니다.
- 프로토콜은 3판입니다(Noise 프롤로그와 서명 도메인이 v3). 이전 판과는 연결되지 않습니다.
- 초대 코드는 256비트 비밀이며, 랑데부 토픽과 서명 키를 HKDF로 유도합니다.

## 대안

- SimpleX 엔진 통합: 상태 복원과 FFI 적합성이 불확실했습니다.
- 자체 서버 운영: 운영자 의존과 계정 DB가 생깁니다.

## 결과

- 이 구성에서 static 키가 일회용이므로 XX의 static 교환이 신원 결속에 기여하지 않고, 실제 결속은 서명이 맡습니다. 같은 효과를 NN 패턴과 서명으로도 얻을 수 있어, XX를 유지하는 이유는 표준 패턴을 그대로 쓰는 단순함입니다.
- relay는 IP, 시간, 이벤트 크기를 볼 수 있습니다. 패딩이 없고 재연결 토픽이 고정이라는 한계가 알려져 있습니다([SECURITY.md](../../SECURITY.md#known-weaknesses)).
- 처음에는 지문을 64자리 hex로 보여 줘서 사람이 앞부분만 비교하기 쉬웠고, 커밋이 없어서 공격자가 그 접두사를 맞추는 탐색이 가능했습니다. 짧은 확인 코드와 커밋 단계로 바꿔 이를 막았습니다(SF-011). 남은 한계는 코드가 약 40비트라서 중간자가 한 번의 시도에서 맞출 확률이 2^-40이고, 시도를 반복할 수 있다는 점입니다. 시도마다 초대 코드를 아는 상대가 새로 연결해야 하고 사용자가 불일치를 보게 됩니다.
- 이전 판(v2) 상대와는 핸드셰이크가 실패하며 화면은 그 원인을 구분해서 알려 주지 못합니다. 두 사람이 같은 버전을 써야 한다는 점을 문서로만 안내합니다.
- 프로토콜 조합은 외부 감사를 받지 않았습니다.
