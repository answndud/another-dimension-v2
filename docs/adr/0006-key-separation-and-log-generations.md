# ADR 0006: 용도별 키 분리와 대화 로그 세대

- 상태: 채택
- 관련: [SF-010](../security-fixes.md), [SF-019](../security-fixes.md)

## 맥락

저장 키 하나가 인덱스, 연결 키 저장소, 연락처, 대화 로그를 모두 암호화했습니다. 또 로그는 파일의 어느 시점인지 알 수 없어서, 이전 파일을 되돌리거나 끝을 자르면 남은 레코드가 모두 인증되었습니다.

## 결정

1. 저장 키에서 용도마다 다른 HKDF 라벨로 키를 파생해 쓰고, 파일 이름 HMAC 키와도 겹치지 않게 합니다. 새 형식은 ADIDX2, ADLKEY2, ADPEER2, ADCONB2, ADLOG3입니다.
2. 형식을 바꿀 때는 새 매직 문자열과 함께 **이전 형식 읽기를 유지**하고, 열거나 다시 쓸 때 새 형식으로 바꿉니다. 이전 형식 읽기 테스트를 함께 둡니다.
3. 대화 로그(ADLOG3)는 헤더에 무작위 세대 id를 두고 모든 레코드의 인증 데이터에 넣습니다. 교체·삭제·병합은 새 세대를 만듭니다.
4. 별도의 암호화된 앵커 파일이 대화마다 세대 id와 레코드 수를 기억합니다. 열 때 비교해 짧아졌거나 모르는 세대면 한 번 경고하고, 열기는 막지 않습니다. 교체는 이름을 바꾸기 전에 새 세대를 `pending`으로 먼저 기록합니다.
5. 경고만 하고 막지 않는 이유는, 충돌 직후의 정상 상태와 변조를 완전히 구분할 수 없고, 잠가 버리면 사용자가 자기 기록을 잃기 때문입니다.

## 근거

단일 기기에는 신뢰할 수 있는 카운터가 없어서, 모든 파일을 함께 되돌리는 공격은 막을 수 없습니다. 앵커는 파일 하나만 바꾸는 공격의 비용을 올립니다.

## 대안

- 로그 안에 끝 표시: 잘린 끝과 구분되지 않습니다.
- 변조 시 열기를 거부: 충돌 복구와 구분하지 못해 오탐이 데이터 손실이 됩니다.

## 결과

앵커는 메시지를 저장할 때마다 다시 쓰입니다(대화가 매우 많을 때의 비용은 측정하지 않았습니다). 한계는 SF-019와 SECURITY.md에 있습니다.
