# ADR 0004: 백업 형식 버전 정책과 구형 형식

- 상태: 채택(현재 형식 정책), 제안(구형 형식 차단)
- 관련: [README](../../README.md)의 백업 형식 표

## 맥락

백업은 사용자가 파일로 직접 옮기므로 오래된 파일이 계속 들어옵니다. 형식이 개선될 때마다 이전 형식을 읽을 수 있게 두면 보호가 약한 형식이 공격 표면으로 남습니다.

## 결정

1. 새로 만드는 백업은 항상 최신 형식입니다. 단일 대화는 ADBACK7, 묶음은 ADPACK3입니다.
2. 최신 형식은 파일마다 무작위 ID, 프레임 인덱스, 종료 프레임을 인증 데이터에 결속하고, 묶음은 대화 수·순서·자식 바이트를 HMAC으로 인증합니다. 선택적 비밀번호는 Argon2id로 유도하고 신원 키와 HKDF로 결합합니다.
3. 형식을 바꿀 때는 새 매직 문자열을 추가하고 이전 형식 읽기는 유지합니다. 기존 데이터를 열지 못하게 하는 변경은 하지 않습니다.
4. **제안(미구현)**: 보호가 약한 구형 형식(ADBACK2, ADBACK6, ADPACK1–2 등)은 기본적으로 거부하고, 사용자가 위험을 확인했을 때만 가져옵니다. 이때 가져온 메시지는 미검증으로 표시합니다.

## 근거

ADBACK2는 키가 비밀번호에서만 유도되고 메시지에 서명이 없습니다. 비밀번호를 아는 사람은 상대가 보낸 것처럼 보이는 기록을 만들어 병합시킬 수 있습니다. 현재는 이 형식을 경고 없이 가져오므로, 4번 결정이 구현될 때까지 [SECURITY.md](../../SECURITY.md#known-weaknesses)에 한계로 기록합니다.

## 대안

- 구형 형식을 영구히 지원: 위조 경로가 남습니다.
- 구형 형식 즉시 삭제: 사용자가 가진 오래된 백업을 열 수 없게 됩니다.
- 한 번 변환하는 도구 제공: 장기적으로 유력하지만 범위가 큽니다.
