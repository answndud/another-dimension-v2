# ADR 0003: 접속 코드(AD2) 형식

- 상태: 채택 (한계 문서화)
- 관련: `src/identity.rs`

## 맥락

전화번호·이메일·계정 서버 없이 같은 신원을 다른 기기에서 복원해야 합니다.

## 결정

앱이 32바이트 무작위 시드를 만들고, 사용자가 개인 접속 코드를 직접 보관합니다. 코드를 입력하면 시드를 복원하고 거기서 서명 키와 로컬 저장 키를 HKDF로 유도합니다. 추가 코드를 발급할 수 있습니다.

- `AD1-` 코드는 시드를 hex로 그대로 담은 구형입니다. 계속 읽을 수 있습니다.
- `AD2-` 코드는 시드를 ChaCha20-Poly1305로 감싼 형태이고, 코드마다 새 무작위 래핑 키와 nonce를 씁니다.

## 정직한 평가

(2026-11-23: 코드 주석과 테스트로도 같은 사실을 고정했습니다. `identity.rs`의 형식 설명과 `a_code_is_the_whole_secret_...` 테스트가 이 성질이 바뀌면 실패합니다.)

AD2 코드는 **래핑 키가 코드 안에 함께 들어 있습니다.** 따라서 암호화가 기밀성을 더하지 않습니다. 코드를 가진 사람은 누구나 시드를 복원합니다. AD2의 효과는 같은 신원에서 서로 다른 문자열을 여러 개 만들 수 있다는 것뿐입니다. 이미 발급한 코드를 개별로 폐기할 수도 없습니다.

## 대안

- 사용자 비밀번호로 코드를 보호: 분실 지점이 하나 더 생기며 아직 도입하지 않았습니다.
- 서버 계정: 중앙 서버를 만들지 않는 목표와 맞지 않습니다.

## 결과

- 코드 유출은 곧 신원 유출입니다. 분실하면 복구할 수 없습니다.
- 기존 코드와의 호환성을 위해 형식은 바꾸지 않았고, 문서와 주석에서 이 성질을 정확히 설명합니다.
