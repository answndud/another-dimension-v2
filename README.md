# Another Dimension v2

Apple Silicon Mac에서 실행하는 로컬 1:1 텍스트 채팅 앱입니다. Rust 프로그램이 로컬 웹 화면을 제공하고, 대화는 기기 안에 암호화해 저장합니다. 중앙 계정 서버나 자동 클라우드 동기화는 사용하지 않습니다.

## 설치와 실행

1. Xcode Command Line Tools와 Rust stable(Cargo 포함)을 설치합니다. macOS 터미널에서 `xcode-select --install`을 실행하고, [rustup.rs](https://rustup.rs)의 안내에 따라 stable toolchain을 설치할 수 있습니다.
2. 저장소를 내려받고 프로젝트 디렉터리에서 실행합니다.

```sh
git clone https://github.com/answndud/another-dimension-v2.git
cd another-dimension-v2
cargo run --release
```

의존성이 이미 로컬에 준비되어 있으면 `cargo run --offline`을 사용할 수 있습니다. 처음 빌드에는 Cargo 의존성 다운로드가 필요할 수 있습니다.

터미널에 표시된 `http://127.0.0.1:포트/` 주소를 지원되는 Chromium 계열 브라우저에서 엽니다. 앱이 터미널에 발급한 일회용 로컬 연결 코드를 화면에 입력합니다. 이 연결 코드는 개인 접속 코드와 다릅니다. 새 신원은 화면에서 개인 접속 코드를 생성해 별도 안전한 곳에 저장한 뒤 로그인합니다. 연결 코드는 만료되거나 한 번 사용된 뒤 다시 쓸 수 없습니다.

## 개인 코드와 대화 연결

- 개인 접속 코드는 본인 신원을 다른 지원 기기에서 복원하는 비밀입니다. 상대에게 보내지 마세요. 분실하면 운영자가 복구할 수 없고, 코드를 가진 사람은 같은 신원을 복원할 수 있습니다. 추가 코드를 발급해도 이미 발급된 코드 사본을 폐기하지는 못합니다.
- 새 대화에서 초대 코드를 만들고 상대에게 별도 연락 수단으로 전달합니다. 양쪽 화면의 확인 지문을 그 별도 경로로 비교한 후 각자 확인해야 메시지를 주고받을 수 있습니다. 앱은 지문 비교가 실제로 안전한 경로에서 이루어졌는지 확인할 수 없으며, 지문은 현실 인물의 신원을 증명하지 않습니다.
- 확인한 상대는 대화 목록에서 다시 연결할 수 있습니다. 상대 또는 본인의 신원이 바뀌면 새 초대와 확인이 필요할 수 있습니다. 기존 대화를 새 신원에 연결할 때는 사용자가 해당 대화를 명시적으로 선택하고 이전 신원을 확인해야 합니다. 신원 계보만으로 같은 사람임을 증명하지 않습니다.

## 기록과 수동 백업

대화 기록과 확인된 상대 관계는 개인 코드에서 유도한 키로 암호화해 로컬에 보관합니다. 대화 화면에서 상대가 가진 누락 기록을 확인하고, 전송 동의와 최종 병합 동의를 각각 선택할 수 있습니다. 복원은 상대가 보유하고 있는 기록에 한정됩니다. 서명은 발신 키와 메시지 변조를 확인하는 데 쓰이며 실제 인물, 기록의 완전성 또는 메시지의 진실성을 증명하지 않습니다. 구형 서명 없는 기록은 미검증으로 표시되며, 본문과 시각이 같은 구형 메시지의 중복 판정에는 한계가 있습니다.

관리 메뉴의 대화 기록 관리에서 선택한 대화를 암호화 파일로 내보내고 다른 기기에서 가져올 수 있습니다. 한 대화 또는 여러 대화를 선택해 백업할 수 있고, 단일 대화 백업에는 선택적 백업 비밀번호를 설정할 수 있습니다. 확인된 상대의 신원 관계 백업은 별도 관리 화면에서 내보내고 가져옵니다. 백업 파일과 개인 접속 코드는 별도로 보관해야 합니다. 파일은 앱이 자동 업로드하지 않으므로 USB나 사용자가 선택한 저장소로 직접 옮기세요.

새로 내보내는 단일 대화 백업은 ADBACK7, 대화 묶음은 ADPACK3 형식입니다. ADBACK7은 백업별 임의 식별값으로 각 프레임과 완료 정보를 결속하고 상대 공개 ID를 암호화합니다. ADPACK3은 대화 수·순서·길이·파일 내용을 인증합니다. 모든 자식 백업의 형식·인증과 묶음 인증이 완료되기 전에 기존 기록이나 상대 관계를 적용하지 않습니다. 두 형식은 전체 파일 크기에 앱 고정 16 MiB 제한을 두지 않고 작은 단위로 처리합니다. 실제 크기는 사용 가능한 저장 공간과 운영체제·브라우저가 처리할 수 있는 파일 크기에 따릅니다. 이전 ADBACK1–6과 ADPACK1–2도 가져올 수 있습니다. 메모리 기반 호환 경로인 ADBACK1–5와 ADPACK1은 파일당 16 MiB까지 지원하며, 스트리밍 형식인 ADBACK6과 ADPACK2에는 이 앱 파일 크기 제한이 없습니다. 특히 ADBACK6은 상대 공개 ID가 평문이며, 비밀번호 없는 백업은 다른 파일의 같은 순번 프레임을 바꿔도 탐지하지 못할 수 있습니다. ADPACK1–2는 묶음의 대화 수·순서를 인증하지 않아 대화를 제거·재배열·교체해도 묶음 수준에서 탐지하지 못할 수 있습니다. ADPACK2 자식은 구형 ADBACK6이므로 상대 공개 ID와 프레임 결속 한계도 이어집니다. 가져오기 화면은 이 구형 형식의 한계를 알리고 확인을 요구합니다. 이 파일 크기 제한은 로컬 기록 보관량 제한이나 자동 삭제를 뜻하지 않습니다. ADBACK1–7은 암호화된 백업 형식이며, 구형 파일의 인증 범위는 버전별로 다릅니다. ADBACK1/3/4/5/6/7은 같은 신원에 필요한 개인 코드가 있어야 합니다. ADBACK2는 기존 신원과 백업 비밀번호가 모두 필요합니다. 구형 백업에 관계 정보가 없으면 과거 키를 자동으로 신뢰하지 않습니다. ADPACK3은 묶음 전체 인증 뒤 적용을 시작합니다. 그 뒤 저장 오류가 나면 앞서 적용한 대화 수와 오류를 표시하며 일괄 롤백하지 않습니다. 구형 묶음은 형식별 검증 범위가 다릅니다. 재보호와 저장은 새 파일을 사용합니다. 원본 백업은 덮어쓰거나 자동 삭제하지 마세요.

백업을 가져오거나 내보내는 동안 앱이 비정상 종료되면 신원별 `~/Library/Application Support/Another Dimension v2/<신원 ID>/.backup-transfer/` 폴더에 전송용 임시 파일이 남을 수 있습니다. 앱은 이 폴더의 잔여물을 자동 정리하지 않습니다. 정리가 필요하면 앱 프로세스를 모두 종료한 뒤 해당 폴더에서 앱이 만든 `*.backup`, `bundle-child-*.tmp`, `bundle-import-child-*.tmp` 파일만 확인해 삭제하세요. 저장해 둔 백업 원본이나 폴더의 다른 파일은 삭제하지 마세요. 비정상 종료 후 잔여물이 남는 상황은 별도로 재현하지 않았습니다.

기록은 자동으로 삭제되지 않습니다. 사용자가 대화 전체, 선택한 메시지 또는 날짜 범위 삭제를 실행할 수 있습니다. 로컬에서 삭제해도 상대방 기록과 백업 파일은 삭제되지 않습니다. 저장장치·운영체제 스냅샷에서 완전히 복구 불가능하게 지운다고 보장하지 않습니다.

## Relay와 Tor 설정

기본 설정은 일반 연결입니다. 로그인 후 메뉴의 **연결 설정**에서 relay 주소 목록과 연결 모드를 관리할 수 있습니다. 주소 목록은 한 줄에 하나씩 입력하며 `wss://`만 허용됩니다. 목록 변경은 저장 후 서버를 재시작해야 적용됩니다. 앱은 실행 중 설정된 relay 목록에 연결을 시도하지만 서비스 가용성이나 상대와 공통 relay가 항상 있다는 것을 보장하지 않습니다.

Tor 모드를 사용하려면 Tor 서비스를 별도로 설치·실행하고, 그 서비스가 제공하는 로컬 SOCKS 주소를 설정에 입력하세요(예: `127.0.0.1:9050`; 설치 방식에 따라 포트가 다를 수 있음). 앱은 Tor를 설치·실행하지 않고, 지정한 SOCKS 서비스가 실제 Tor인지 확인하지 않습니다. SOCKS 또는 relay 연결이 실패하면 직접 연결로 우회하지 않습니다. 모드를 저장한 뒤 서버를 종료하고 다시 실행해야 적용됩니다.

Tor 모드는 앱의 relay 연결에만 적용됩니다. 메시지 링크를 열 때 표시되는 외부 브라우저는 Tor를 사용하지 않을 수 있으며 앱은 그 브라우저의 네트워크 경로를 제어하지 않습니다. Tor가 완전한 익명성이나 트래픽 상관분석 방지를 보장하지 않습니다.

## 범위와 확인 상태

이 프로젝트는 macOS Apple Silicon을 주요 대상으로 합니다. 실제 브라우저 레이아웃, 사용자 환경의 Tor 경로, 공개 relay의 가용성과 상호운용은 별도 환경에서 확인해야 합니다. 독립 보안 감사는 수행되지 않았으며, 암호화 구현을 보안 보증으로 해석해서는 안 됩니다.
